**TechBlocks** est une plateforme de documentation collaborative orientée développeurs, taillée dans le même bois que Linear et Notion : des documents vivants découpés en blocs — markdown, code avec coloration syntaxique, diagrammes Mermaid, endpoints API et callouts. Un éditeur fluide, un autosave qui ne laisse rien s'échapper, un historique de révisions complet, le tout dans un thème sombre premium. Et surtout, c'est un projet **100% vibe coded** : chaque écran, chaque endpoint et chaque bloc a d'abord été brainstormé, challengé puis spécifié en dialoguant avec des IA, avant qu'une seule ligne de code ne soit écrite.

## 領域展開 · La genèse

Ce dépôt n'est pas sorti de nulle part : il est la mise en pratique directe de deux formations complétées en septembre 2026.

Le **Google AI Professional Certificate**, sur Coursera, est un parcours de 8 cours et environ 13 heures signé Google, suivi par plus de 1,5 million d'apprenants — fondements de l'IA, brainstorming et planification, recherche et insights, rédaction, création de contenu, analyse de données, construction et déploiement d'applications. C'est dans ces cours que j'ai appris à **brainstormer une idée avec une IA** et à affûter mon **prompt engineering** : le cahier des charges de TechBlocks, son schéma SQL, ses specs de blocs et ses endpoints sont nés de ces échanges, avant même d'ouvrir l'IDE.

**Claude Code in Action**, sur la plateforme Skilljar d'Anthropic, est la formation officielle et gratuite pour piloter Claude Code : diriger le travail, configurer l'agent (CLAUDE.md, skills, permissions, hooks), automatiser les tâches répétitives (routines, mode headless, GitHub Actions) et vérifier le travail non supervisé. C'est elle qui a donné sa méthode à ce dépôt : instructions d'équipe, règles de style, conventions API, tests systématiques et commits fréquents — toute la discipline visible dans l'historique de ce repo en vient.

## 術式 · Les 5 blocs

| Sceau | Bloc | Super pouvoir |
| --- | --- | --- |
| 呪 | **Markdown** | Texte riche : titres, listes, citations, code inline, liens |
| 術 | **Code** | Coloration syntaxique, numéros de ligne, nom de fichier |
| 界 | **Mermaid** | Diagrammes rendus en direct — flowcharts, séquences, états |
| 電 | **API Endpoint** | Méthode, headers, body de requête et exemple de réponse |
| 符 | **Callout** | Notes, avertissements et alertes stylés |

## 電 · La stack

| Couche | Arsenal |
| --- | --- |
| **Frontend** | React 19 · Vite 8 · TypeScript strict · Tailwind 4 · shadcn/ui · Framer Motion · CodeMirror 6 · Mermaid 12 · axios |
| **Backend** | Spring Boot 3.5 · Java 21 · Spring Security (JWT Bearer) · JPA/Hibernate · Flyway · Lombok |
| **Données** | PostgreSQL 16 (Docker Compose) |
| **Qualité** | Vitest + React Testing Library + msw · JUnit 5 + Mockito · Testcontainers · oxlint |

## 符 · L'architecture

```mermaid
%%{init: {"theme":"dark", "themeVariables": {"primaryColor":"#16281E", "primaryTextColor":"#C9D4C6", "primaryBorderColor":"#2A3A2E", "lineColor":"#788C5D"}}}%%
flowchart LR
    A["React 19 · Vite 8<br>Éditeur de blocs"] -->|"REST /api/v1<br>JWT Bearer"| B["Spring Boot 3.5<br>Controller → Service → Repository"]
    B --> C[("PostgreSQL 16<br>techblocks")]
    B --> D["Flyway<br>migrations"]
```

Le frontend envoie tout par l'API `/api/v1` avec un token JWT Bearer, sauf l'inscription et la connexion. L'autosave de l'éditeur débounce 1,5 seconde puis pousse les blocs en un seul `PUT`. Les erreurs suivent le format Problem Details (RFC 9457) avec les bons codes HTTP — 400, 401, 403, 404, 409, 422, 500 — et la pagination répond toujours en `{ items, total, page, size }`.

## 起動 · Démarrage rapide

```bash
docker compose up -d                    # PostgreSQL 16 (db: techblocks)
cd backend && ./mvnw spring-boot:run    # API Spring Boot sur :8080
cd frontend && npm run dev              # App sur http://localhost:5173
```

Tests et vérifications avant toute livraison :

```bash
cd backend && ./mvnw test
cd frontend && npm run test && npm run lint && npx tsc --noEmit
```

## 契約 · L'API

| Méthode | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/api/v1/auth/register` | Inscription (BCrypt) |
| `POST` | `/api/v1/auth/login` | Connexion → JWT Bearer |
| `GET` `POST` | `/api/v1/workspaces` | Lister / créer un workspace |
| `GET` | `/api/v1/workspaces/{id}/members` | Membres d'un workspace |
| `GET` `POST` | `/api/v1/workspaces/{workspaceId}/documents` | Documents d'un workspace |
| `GET` `PUT` `DELETE` | `/api/v1/documents/{id}` | Lire / renommer / supprimer un document |
| `PUT` `POST` | `/api/v1/documents/{id}/blocks` | Autosave des blocs (batch) |
| `DELETE` | `/api/v1/blocks/{blockId}` | Supprimer un bloc |
| `GET` `POST` | `/api/v1/documents/{id}/revisions` | Révisions / snapshot du document |

## 品質 · L'exorcisme des bugs

Chaque couche est couverte : `@WebMvcTest` et `@DataJpaTest` côté backend, Testcontainers pour la vraie base PostgreSQL, et côté frontend des tests comportementaux Vitest + React Testing Library avec msw — rendu des 5 blocs, menu slash, autosave avec debounce et PUT batch. La règle est sacrée : on ne modifie jamais un test pour faire passer du code ; la cause racine vit dans le code, pas dans les specs des tests.
